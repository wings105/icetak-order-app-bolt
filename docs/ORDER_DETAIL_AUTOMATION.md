# Order detail automation

Status: backend PRODUCTION; controlled Admin V2 desktop/mobile VERIFIED. Existing hosted Task Workspace components consume compatible status/remark/evidence fields; no frontend publication is required. Source publication to the existing public repository was authorized by the owner on 20 October 2026.

Order System owns `task_detail_automation` (one observation per Task ID), immutable change events and a private runtime/lease. Initial order/task events wake `task-detail-worker`; cron also polls every minute. This continues without an open browser. New order signals are recorded before the ClickUp task is available. The worker evaluates each item immediately into private order_detail_automation observations while no task exists, then transfers the exact-SKU baseline/evidence into the task when linked. Intake polls rotate through up to 10 pending orders per run, capped at 50 items/order; truncation remains visible. Task creation/linking wakes the worker again. Dashboard coverage remains the active ORDER LIST projection. Up to 100 oldest-checked active tasks are examined per run; larger cohorts rotate. Closed/shipped/cancelled/deleted tasks are excluded. The worker has a three-minute lease and source/version checks; unchanged runs update only the check timestamp and do not append duplicate audit events. A derived dispatch failure cannot reject canonical order ingestion.

For each task, reuse the simple product rules in TASK_WORKSPACE.md. Read canonical checkout note, scoped Shopee chat and exact matched WhatsApp context. Multi-item notes require an explicit unique label/SKU; copied combined ClickUp wording is split when labelled, and ambiguous repeated wording is excluded. No array-position assignment. `EXAMPLE TURNS 5` remains exact rather than being reformatted as a name/age pair.

If missing, record a 30-minute recheck due from placement; new customer detail can complete it earlier. At/after the due instant the worker records the recheck, then continues watching for messages while active. This is a read/reassessment timer, not a customer-message follow-up.

The Inbox service-only invoker `icetak_task_automation_context` wraps the existing cutoff-aware context. It additionally finds WhatsApp using the order's exact normalized phone and Shopee by exact buyer ID where a session link is absent. A unique conversation and no competing active order are required. Unknown previous links restrict expansion to placement; known earlier cutoffs are preserved. Reads are capped at 120 messages per binding, and ambiguous/truncated sources require review. No contacts/conversations are merged or linked by this reader. Inbound provider data must already be ingested; it does not fetch a new provider API history.

After a persisted complete observation, incoming questions add separate admin attention while preserving complete design information. Meaningful text/image/specification changes reopen readiness and block print-ready indication. Acknowledgements, stickers/reactions and system messages do not open attention. Unrecognized substantive messages conservatively request admin attention. Changes preserve the last complete values and message evidence, including a production-started warning. The existing current-source admin brief confirmation acknowledges attention; repeated polling cannot silently clear it. Operational replies alone do not expire an approved design fingerprint.

Automatic remarks are separate from native manual work notes, source statuses, customer approvals and final artwork QC. This automation creates no order/payment/ClickUp task and sends no customer message. Rules are deterministic parsing with uncertainty sent to admin; no AI-provider call/cost was introduced.

## Runtime and access

Order `task-detail-worker` uses its own generated private server token, and `task-workspace` retains JWT/active-admin permissions. The worker token is generated/consumed server-side and never returned to a browser. Task and initial-order observation/audit tables have RLS and no browser grants/policies; privileged RPCs grant EXECUTE to service_role only. Inbox `task-brief-media` retains its existing private bridge authentication. Private schema definer dispatch/signal helpers have empty search_path and no public/browser EXECUTE.

Pause: `update task_detail_private.runtime set enabled=false where id;`. Resume by setting true; cron remains the recovery trigger. Health: runtime last_started_at/last_finished_at/last_result; audit: task_detail_automation_events; check timestamp: task_detail_automation.last_checked_at. Migrations under inbox-migrations apply only to Unified Inbox; all other new migrations apply to Order System. Deploy the worker before the activation migration.
